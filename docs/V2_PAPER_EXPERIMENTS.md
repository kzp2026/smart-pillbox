# 论文实验中心使用说明

适用入口：`v2/app.py` → 论文实验中心。原站与外部爬虫不改动；本功能不自动采集平台数据、不调用收费模型。

1. 输入论文研究产品名称，上传评论 CSV/XLSX，或从该产品导入历史读取原文件。
2. 映射评论/评分/日期/版本/渠道列，填写八项来源说明。检查清洗排除数，再“准备并检查数据集”。
3. 下载空白人工标注模板。情感单选正面/中性/负面；需求多选固定六类，使用 `|` 分隔，无命中选无明确需求。多人盲标后先仲裁，每评论每任务仅一行最终真值。匿名标注者列不可为空。
4. 预先划分 train/dev/test，所有方法使用同一 test ID。不要在 test 上选择参数、改规则或剔除错误样本；注意近重复和同产品同批次泄漏。
5. 运行基线：字符 TF-IDF + KMeans 做主题探索；词典情感有无否定处理做对照；全规则与首命中做需求消融。可选运行 SnowNLP。此处未运行 BERTopic，不得在论文中误标方法名。
6. 要验证自己的模型，导入候选预测，列为 comment_id/task/method/prediction；填写方法版本、参数、Prompt/模型版本、训练范围及原运行 ID。预测不得来自人工真值拷贝；必须覆盖全部 test 样本。外部方法在此仅评价，不自动重跑。
7. 从同产品历史关联真实设计方案，下载评分模板，组织独立专家/用户评价。量表 1–5：1明显不满足、2较差、3基本满足、4较好、5充分满足。评审者匿名 ID、角色、方案 ID 和维度必须准确；专家与用户分别统计。需在论文交代评审人数、招募标准、盲评与呈现顺序。
8. 保存实验后查看证据矩阵；在“复现与下载”准备 DOCX、PNG、CSV、JSON 或完整 ZIP。实验不依赖会话存储，可以从论文实验历史重新打开。

## 复现

证据包保存清洗评论而非原始上传中的账号信息。保管好原文件供来源审查；系统只验证哈希，不能认证来源真实性。环境清单含版本，manifest 含算法源码摘要。源码应使用对应 Git 版本保存。

```powershell
Set-Location D:/解压目录/source
python -m v2.research.reproduce ../experiment.json
```

归档 source 含最小可运行源码白名单；固定同一依赖后，可比较 predictions/topics/mappings/metrics，代码摘要不同会拒绝复现。外部候选模型仅重放已保存预测。每个 ZIP 文件条目摘要列于 manifest.json，manifest 自身不包含在自校验范围。含源码的论文 ZIP 不使用旧十阶段的归档恢复入口；论文历史仍在私有运行库中打开。

## 论文可支持与不可替代的部分

可以支持：系统实现、可复现的清洗与分析流程、需求—功能—结构的可追溯候选映射、真实输入下计算的对照表和人评统计。

不能自动证明：采集合法/真实、标注质量、领域泛化、方法优越或创新、显著性、工程可制造性、论文录用。软件测试数据不计入论文研究样本。无真实标注/评分时，报告会保留缺口，不产生虚构数据。

自动遮盖只覆盖手机号/邮箱，公开前仍需人工检查姓名、地址和特殊可识别描述。导出 CSV 对公式前缀加单引号，JSON 保存用于复现的原数值/文本。
